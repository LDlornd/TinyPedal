# Live for Speed 接入

本分支通过本机 UDP 读取 LFS 的 OutSim 和 OutGauge，并通过本机 InSim TCP 自动获取当前赛道代码、多车位置、本地驾驶者圈时和分段事件。不安装额外插件，不写入游戏内存，不自动修改游戏配置。

读取方式参考 [LFS-Race-Engineer 的协议实现](https://github.com/fermga/LFS-Race-Engineer/tree/main/src/lfs_telemetry/telemetry/protocol)。协议来源及使用条件可查阅 [LFS 开发者文档](https://www.lfs.net/programmer/insim)、[OutSim](https://en.lfsmanual.net/wiki/OutSim) 和 [OutGauge](https://en.lfsmanual.net/wiki/OutGauge)，并以当前游戏安装目录中的 `docs/OutSimPack.txt` 为准。

## 配置与启动

先退出 LFS，并自行备份游戏根目录的 `cfg.txt`。在该文件中设置以下条目；若条目已经存在，请修改原条目，避免重复添加：

```text
OutSim Mode 1
OutSim Opts 1ff
OutSim Delay 1
OutSim IP 127.0.0.1
OutSim Port 30000
OutSim ID 0
OutGauge Mode 1
OutGauge Delay 1
OutGauge IP 127.0.0.1
OutGauge Port 30001
OutGauge ID 0
```

在 TinyPedal 的“API”菜单中选择 `Live for Speed`，再打开“选项”：

| 配置键 | 含义 |
| --- | --- |
| `outsim_port` / `outgauge_port` | 两个不同的本机 UDP 端口，须与游戏一致 |
| `enable_auto_track_name` | 默认开启，通过 InSim 自动识别赛道，无需填写 `track_name` |
| `insim_port` | 本机 InSim TCP 端口，默认 `29999`，须与游戏开启的端口一致 |
| `track_name` | 关闭自动识别时使用的手动赛道名称，例如 `BL1`；手动模式下换图后须更新 |
| `driver_name` | 人工填写的驾驶者名称或昵称 |
| `track_length` | 赛道长度，单位米；保留 0 时在首次过线后估算 |
| `steering_range` | 游戏内方向盘总转角，单位度；未知时保留 0 |
| `engine_rpm_max` | 游戏车辆的最高转速，单位 RPM；未知时保留 0 |
| `fuel_capacity` | 油箱容量，单位升；未知时保留 0，只使用油量比例 |
| `connection_timeout` | 数据过期秒数，默认 1 秒 |

自动识别需要先在 LFS 的聊天输入框中执行：

```text
/insim 29999
```

此命令开启当前游戏进程的 InSim 接口；重新启动游戏后需要再次开启。也可以在启动 LFS 时添加 `/insim=29999` 参数，让游戏每次启动都开启接口。TinyPedal 会每隔 2 秒尝试连接，因此先启动哪一个程序都可以。若已为其他工具开启 InSim，请使用同一端口，无需重新开启；InSim TCP 可同时连接多个程序，与 UDP 端口独占不同。

自动识别使用游戏发出的短代码，例如 Blackwood GP 为 `BL1`、反向为 `BL1R`。检测到的代码保存在运行时快照中，状态栏、地图和驾驶记录共用这一来源，不会反复写入预设中的手动字段。切换赛道后自动更新，不需要重新应用 API 选项。开放布局使用游戏报告的代码，不额外识别自定义布局文件名。

自动模式下，InSim 未开启、断开或尚未提供赛道时，不会用之前手动填入的名称代替，避免新赛道被记到旧名称下。状态栏会显示 InSim 状态和所需的 `/insim` 命令；此时叠加层仍按“自动隐藏”设置处理。关闭 `enable_auto_track_name` 后，可以继续使用原来的手动流程；手动模式不创建 InSim 连接。当前连接使用空的 InSim 管理员密码，若游戏设置了管理员密码，请先使用手动模式。

人工补充的数值须与游戏及车辆实际设置一致。赛道长度保留 0 时，程序根据过线前后的固定赛道距离尺和速度估算，仅供进度显示；已有准确数值时可以手动填写，但换图后须相应更新。

应用选项后启动 LFS，开启 InSim，进入车辆并使用驾驶舱或自定义车内视角。状态栏显示 `OutSim 1ff | BL1` 表示已收到扩展物理数据和当前赛道。游戏退出、暂停或切换到不输出遥测的视角后，过期数据会使叠加层隐藏。恢复驾驶后继续接收，无需重新绑定端口。

默认 `Mode 1` 只采集驾驶；若改成 `Mode 2`，回放也可能被采集。两路 UDP 本身不足以可靠辨认驾驶与回放，分析时请注明数据来源。

## 数据范围

| 数据 | 来源与边界 |
| --- | --- |
| 速度、位置、姿态、加速度、角速度 | 旧版及扩展 OutSim |
| 油门、刹车、离合 | 扩展 OutSim；旧版格式可由同时有效的 OutGauge 补充 |
| 转向输入、手刹、圈内距离 | 扩展 OutSim |
| 四轮载荷、悬架压缩、轮速、滑移率、滑移角、轮胎空气温度 | 扩展 OutSim，内部统一为 FL、FR、RL、RR |
| 挡位、转速 | 扩展 OutSim；OutGauge 也可提供 |
| 车型或 MOD ID、油量比例、增压、水温、油温、仪表灯 | OutGauge |
| 当前赛道代码及正反向、开放布局标志 | InSim `IS_STA.Track` |
| 其他车辆的位置、朝向、速度及车辆身份 | InSim `IS_MCI` 与 `IS_NPL`，请求每 20ms 更新，用于地图车辆标记和雷达 |
| 上一圈成绩、已完成圈数、分段、进出维修区 | InSim 本地人类驾驶者的 `IS_LAP`、`IS_SPX`、`IS_PLA` 等报文 |
| 当前圈时间、地图及实时圈时对比 | OutSim 固定赛道尺识别过线，结合 InSim 完圈确认，复用 TinyPedal 原有录制模块 |

此版本没有接入 HLVC 有效圈认证、多人排名、天气和调教文件自动备份。这里的有效圈表示收到与过线匹配的 InSim 计时成绩，不表示满足热圈排行榜规则。轮胎压力、胎面温度、轮胎磨损、刹车温度、实际发动机扭矩和标准化力反馈也不在这两路 UDP 协议的可用数据中。OutSim 的最大可用扭矩、转向扭矩和胎内空气温度不能当作上述同名近似指标使用。

建议先启用速度表、踏板、转向和悬架行程等有实际来源的组件。依赖赛事、损伤或未提供温度数据的组件应关闭；为兼容既有读取接口，这些组件的部分通道沿用零值或不可用哨兵值，不代表真实测量。

## 线上漫游与雷达

在 API 选项中保持 `enable_auto_track_name` 开启，并在 LFS 执行 `/insim 29999`。启用雷达组件，以及 Vehicles 和 Relative 模块。进入线上服务器驾驶后，状态栏的 `traffic: N` 表示当前收到的其他车辆数，不包括本车；无须先过线、完成一圈或开始比赛。这里使用的是本机 LFS 客户端收到的位置，刷新和延迟也会受到网络同步影响。

本车继续使用 OutSim，其他车辆使用 InSim MCI。超过 16 辆车时，先合并同一组 MCI 报文，再发布完整车辆列表。进入车库、旁观、车辆重置及断线时清除旧位置；超过 `connection_timeout` 未更新的位置也不再显示。带 `CCI_LAG` 标志的车辆暂时不参与显示。

赛道地图的车辆标记也使用这些坐标，但实际道路背景仍依赖已有的 `trackmap/<赛道代码>.svg`。如果只有圆形占位图，其他车辆因缺少圈内距离会堆在起点，不能用它判断实际位置；请先使用雷达。开放布局无需圈时即可使用雷达，但当前流程不会自动生成开放布局路网，也未接入其他车辆的圈内距离、圈时和排名。

## 地图和圈时对比

保持自动识别开启，并在游戏中执行 `/insim 29999`。在 TinyPedal 中启用“赛道地图”和“最佳圈时间差”组件，以及对应的 Mapping、Delta 模块；当前默认预设已开启这两个模块。

首次进入赛道后，状态栏先显示 `timing: cross start/finish`。先正向通过一次起终点，定位圈起点，再连续完成一整圈，途中不要进入维修区、重置车辆或切换视角。过线后约 1 秒，收到匹配的 InSim 成绩才会保存地图和圈时参考。接着继续驾驶，预期地图由圆形占位变为实际赛道形状，时间差开始随位置变化。默认地图保存在 `trackmap/<赛道代码>.svg`，参考圈保存在 `deltabest/<赛道代码> - <车型>.csv`。

当前圈时由 OutSim 时间戳和过线位置估算，精度受采样间隔及过线速度影响；上一圈成绩使用 InSim 毫秒值。地图和时间差使用 `IndexedDistance` 固定赛道尺，而不是随每圈走线变化的 `CurrentLapDist`。叠加层圈数是本轮连续采集观察到的过线次数，导出的 `lap_completed` 才是 InSim 报告的官方圈数。

地图坐标采用 `(Y, X)`，与屏幕纵轴向下的方向一致；导航朝向统一换算为 `Heading + π/2`。之前的 `(Y, -X)` 会把左右弯镜像。旧地图已经保存了取反后的坐标，修复适配器后也需要转换旧 SVG 的地图纵坐标，或先备份旧文件再重新录制；圈时参考 CSV 不需要转换。本次已有的 `FE2.svg` 已备份并转换。后续录制使用修正后的坐标。

暂停至遥测超时、换图、重新入车、车辆重置和大幅位置跳变会丢弃当前半圈，需要重新过线定位。进出维修区的圈不用于录制。已经保存的地图和参考圈继续按赛道、车型加载。关闭自动识别后不建立 InSim 连接，仍能使用原有输入和仪表，但不会确认新的地图或参考圈。旧版 OutSim 和无固定距离尺的开放布局不支持此录制流程；开放布局的自定义计时点也尚未对齐。通用分段接口最多显示三段，超过两个中间计时点时，其余部分合并到最后一段。

## 实现与修改位置

- `lfs_udp.py` 负责定长小端解码、数值检查、两个 socket 和接收线程。旧格式仅接受 64/68 字节，扩展格式仅接受 `1ff` 对应的 280 字节；OutGauge 接受 92/96 字节。其他掩码会拒绝并记录日志。
- `lfs_insim.py` 的 `TrackReader` 管理本机 TCP 连接及线程，请求 InSim 9，接受版本回包报告 9 或 10。初始化通过 `ISF_LOCAL | ISF_MCI` 和 20ms 间隔订阅多车位置，报文格式参考 [InSim 协议](https://en.lfsmanual.net/wiki/InSim.txt)。间隔须为整数毫秒，并按 10ms 的步长设置；20ms 对应每秒 50 次，实际位置刷新仍受游戏和网络同步频率限制。连接和发送超时为 3 秒，接收用 `select` 每 0.2 秒检查一次，空闲轮询不会触发断线。每秒请求一次状态，5 秒没有状态回应则断开重连。只发送初始化、状态和玩家列表查询、保活，不发送游戏控制或聊天消息。`RaceState` 保存本地人类驾驶者状态，AI 和远端车辆不参与本车计时；`CarState` 保存多车位置及身份，`_read_cars` 按 `CCI_FIRST`、`CCI_LAST` 合并多包数据。需要支持 InSim 9 的 LFS（0.7A 或更新版本）；9/10 的实际游戏兼容性仍需运行确认。
- `Telemetry` 创建并关闭 `TrackReader`，通过 `_set_track` 将赛道与遥测放进同一把锁保护的快照。换图、回到游戏入口或连接断开会清空旧物理与仪表快照，并增加重置计数。TCP 状态与 UDP 物理数据没有共同帧编号，不能保证两路切换瞬间完全同步。
- UDP 独立校验递增时间戳，丢弃重复或乱序包。过期后允许接收重新开始的时钟，并更新重置计数。两路时间差超过 250ms 时不合并仪表数据。此同步方式使用最近有效包，不做插值。
- `lfs_reader.py` 把不可变快照映射到现有 `APIDataReader`。协议轮序 RL、RR、FL、FR 在解码时只转换一次。输入不加平滑或死区，位置从 1/65536 米换成米，发动机角速度换成 RPM。地图坐标和 `map_heading` 只在适配层转换，地图录制、车辆标记及导航共用这一约定，原始位置、原始朝向和车身速度计算保持协议坐标。
- `Telemetry._set_cars` 将车辆列表纳入快照锁，`snapshot` 按本地 PLID 排除本车并过滤过期位置。本车始终为索引 0，其余车辆按 PLID 排序；`Vehicle` 的位置、朝向、速度和身份方法按索引读取，供已有 Vehicles、Relative 模块以及地图、雷达共用。`Timing.elapsed(index)` 把 MCI 到达时间投影到 OutSim 时钟，供现有坐标插值使用；两路数据没有共同帧编号，仍可能有同步误差。未接入的其他车辆踏板、油量、圈时和圈内距离使用接口约定的不可用值，不借用本车数据。后续调整位置更新频率从 `MCI_INTERVAL_MS` 入手，扩展其他车辆数据从 `CarState` 和对应读取方法入手。
- `Telemetry._update_timing` 使用固定赛道尺检测正向过线，`_set_race` 合并前后 1 秒内的 InSim 完圈成绩，两者都持同一把快照锁；未确认时不复用更早一圈的成绩。`Lap` 和 `Timing` 接入现有 `module_delta`、`module_mapping`，不另写地图或时间差算法。`MapCoords.is_valid` 允许缺少中间分段线的赛道保存地图。
- 加速度轴沿用参考实现的车身坐标解释；读取接口的纵向符号与现有模块保持一致，制动为正。导出会保留协议原始轴，真实车辆上的轴向和符号仍需手动核对。
- `lfs_connector.py` 创建并管理接收器，复用原有开始、停止和重载入口。绑定失败会显示在接口状态及日志中。没有自动改端口或关闭占用端口的软件。

若其他工具已占用同一 UDP 端口，请先停止该工具，或为 TinyPedal 和 LFS 配置另一对端口。此版本没有增加 UDP 转发功能。

## 最小手动验证

前置条件：已按中文 README 准备依赖和子模块，并安装支持扩展 OutSim 的 LFS。

在仓库根目录执行 `.\.venv310\Scripts\python.exe run.py`，复用已准备好的 `.venv310` 环境。按上面的步骤设置游戏与接口，在 API 选项中保持自动识别开启，清空手动 `track_name` 并应用。先在 LFS 执行 `/insim 29999`，进入 Blackwood GP 驾驶，预期状态栏出现 `OutSim 1ff | BL1` 并显示仪表。切换到另一条赛道或反向布局，预期代码随之更新，无需手动填写；正在进行的旧赛道记录应在新赛道恢复遥测后以 `context_changed` 结束。

速度应与游戏仪表一致，踏板从 0 到 1 变化，左右转向方向正确；驶过路肩时对应车轮的悬架行程变化。请另行核对加速度符号和四轮顺序。

按“地图和圈时对比”一节先过线，再完成完整圈。预期状态变为 `timing ready`，地图文件和参考圈文件生成，下一圈的时间差随位置变化；没有 InSim 成绩时不得生成新参考圈。再重置车辆、进出维修区和暂停超过 1 秒，确认半圈不会被保存。

进入至少有另一辆车的线上漫游服务器，启用 Vehicles、Relative 模块及雷达组件。预期状态栏出现 `traffic: N`（N 大于 0），在尚未过线时就能看到雷达范围内的车辆。让对方分别位于本车前、后、左、右，再转弯核对雷达相对方向；有对应 SVG 地图时，也应看到其他车辆标记移动。再让对方进车库、旁观、离线，确认旧标记消失；回到赛道后应重新出现。超过 16 辆车的服务器应能显示后续报文中的车辆。

随后暂停或退出 LFS，预期约 1 秒后停止使用旧数据；恢复驾驶、重启 API、切换到原有游戏再切回 LFS，预期能重新绑定端口。端口被占用时，预期在状态和日志中看到失败原因。

关闭自动识别并填写 `BL1`，预期无需 InSim 即可按原方式显示；重新开启自动识别后，断开 InSim，预期显示连接状态并停止使用旧赛道名。重启游戏并再次开启 InSim，预期自动重连。

如果游戏反复出现 `InSim guest closed: TinyPedal`，请在 TinyPedal 的“帮助 → 日志”查看 `LFS InSim` 行。成功的版本回应会记录游戏版本、请求版本和报告版本；错误会标明 `connect`、`initialize` 或 `read state` 阶段。版本包长度不符和版本不支持分别记录实际长度、版本值，不再统称为“不支持 InSim 9”。

如果一直停在 `waiting for InSim`，也请检查启动终端中的线程异常。将 `MCI_INTERVAL_MS` 写成 `1000 / 60` 会得到浮点数，无法打包为 InSim 的整数间隔字段；本次改为 `20`，并将 `struct.error` 纳入状态和日志反馈，避免这类打包错误让线程无提示退出。修改代码后须退出并重新启动 TinyPedal，让新代码生效。

本次只做静态复核，尚未用真实 LFS 或 UDP 数据包运行验证。未执行测试，由用户自行验证。
